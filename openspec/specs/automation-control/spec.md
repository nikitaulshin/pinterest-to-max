# CLI и фоновая автоматизация

## Purpose

Дать одному пользователю команды настройки и управления автоматизацией, а также устойчивый фоновый запуск с понятными ошибками и сохранением локальных данных.

## Requirements

### Requirement: Команды управления MVP

Сервис SHALL предоставлять CLI для авторизации Pinterest/MAX, обычной и полной синхронизации, bootstrap, backfill с количеством, просмотра очереди, пропуска и повтора задания, dry-run и фонового запуска.

#### Scenario: AC-01 Доступные команды
- **GIVEN** пользователь запускает справку CLI
- **WHEN** он выбирает команду MVP
- **THEN** справка описывает её обязательные параметры, допустимые состояния и влияние на данные
- **AND** просмотр очереди доступен во время работы фонового процесса без изменения заданий

#### Scenario: AC-02 Ошибка параметров команды
- **GIVEN** команда неизвестна либо количество backfill не является положительным целым числом
- **WHEN** пользователь запускает CLI
- **THEN** команда завершается с ненулевым кодом и понятным сообщением без изменения очереди и внешних постов

### Requirement: Явная настройка единственного канала

Сервис MUST проверять конфигурацию доски, целевого канала, временных слотов и ограничений до автоматического создания постов и не выбирать канал по умолчанию из открытого браузера.

#### Scenario: AC-03 Целевой канал не настроен
- **GIVEN** источник доски известен, но целевой канал или обязательные параметры планирования отсутствуют
- **WHEN** запрашивается фоновая автоматизация или планирование
- **THEN** сервис перечисляет недостающие настройки и не создаёт посты
- **AND** доступные команды авторизации и синхронизации не требуют несвязанных настроек MAX

### Requirement: Периодическая автоматическая работа

Сервис SHALL периодически синхронизировать доску и пополнять отложку без участия пользователя после первоначальной настройки; интервал синхронизации должен быть настраиваемым положительным значением.

#### Scenario: AC-04 Новый пин в фоновом режиме
- **GIVEN** история инициализирована, обе сессии действуют и есть доступные слоты
- **WHEN** пользователь сохраняет новый подходящий пин и наступает очередной цикл
- **THEN** изображение автоматически скачивается, попадает в очередь и передаётся в отложку MAX
- **AND** ручная команда для каждого пина не требуется

### Requirement: Независимость работы с подготовленной очередью

Сервис MUST продолжать безопасную работу с подготовленными изображениями при ошибках или недоступности Pinterest и сохранять импорт при недоступности MAX.

#### Scenario: AC-05 Pinterest недоступен
- **GIVEN** Pinterest недоступен или требует ручного входа, но в очереди есть готовые локальные изображения и MAX доступен
- **WHEN** наступает цикл планирования
- **THEN** доступные изображения продолжают планироваться в MAX независимо от результата синхронизации
- **AND** ошибка Pinterest сохраняется отдельно

#### Scenario: AC-06 MAX недоступен
- **GIVEN** MAX недоступен, а Pinterest доступен
- **WHEN** выполняется очередной цикл импорта
- **THEN** новые изображения сохраняются в очереди без потери и попыток немедленной публикации
- **AND** незавершённая отправка MAX остаётся под правилами сверки, а не сетевого повтора

### Requirement: Ограниченные повторы временных ошибок

Сервис SHALL повторять безопасные операции при временных сетевых ошибках с увеличивающейся ограниченной задержкой, сохраняя причину и возможность дальнейшего восстановления.

#### Scenario: AC-07 Временный сетевой сбой
- **GIVEN** чтение доски, скачивание либо чтение MAX завершилось временной сетевой ошибкой без возможного создания поста
- **WHEN** наступает разрешённое время следующей попытки
- **THEN** повторяется только безопасная операция с сохранённым заданием
- **AND** нет бесконечного быстрого цикла повторов; неопределённая отправка не повторяется этим механизмом

### Requirement: Остановка при изменении интерфейса

Сервис MUST прекращать затронутую браузерную операцию при неподтверждённой структуре страницы или несовпадении ожидаемых элементов вместо угадывания действия.

#### Scenario: AC-08 Изменился интерфейс
- **GIVEN** ожидаемый элемент или подтверждение результата больше нельзя достоверно определить
- **WHEN** интеграция обнаруживает изменение интерфейса
- **THEN** она прекращает затронутые действия с диагностикой и не выбирает другой элемент наугад
- **AND** потенциально отправленное задание получает неопределённый результат, остальные данные сохраняются

### Requirement: Структурированные логи и приватная диагностика

Сервис SHALL записывать структурированные события операций и ошибок и сохранять диагностические скриншоты ошибок Playwright в приватном локальном хранилище без секретов в логах.

#### Scenario: AC-09 Браузерная ошибка
- **GIVEN** операция Playwright завершилась ошибкой
- **WHEN** формируется диагностика
- **THEN** лог содержит время, сервис, тип операции, доступный ID задания, код ошибки и путь к скриншоту
- **AND** скриншот хранится вне Git вместе с приватными данными
- **AND** если браузер уже недоступен или запись скриншота не удалась, лог явно фиксирует отсутствие скриншота без сокрытия исходной ошибки

#### Scenario: AC-10 Секреты и профили
- **GIVEN** приложение использует авторизованные профили и собирает диагностику
- **WHEN** оно пишет логи или пользователь проверяет отслеживаемые файлы
- **THEN** пароли, коды входа, cookies и токены сессий не попадают в логи или Git
- **AND** БД, изображения, браузерные профили и скриншоты исключены из Git

### Requirement: Постоянный запуск Docker Compose

Сервис SHALL поддерживать фоновую работу через Docker Compose с постоянным хранением SQLite, изображений, профилей и диагностики и корректной остановкой.

#### Scenario: AC-11 Пересоздание контейнера
- **GIVEN** сервис настроен и его данные находятся в постоянном томе
- **WHEN** контейнер останавливают и пересоздают без удаления тома
- **THEN** очередь, история, файлы, профили и диагностика сохраняются
- **AND** возобновление обработки соблюдает правила восстановления и не создаёт повторные посты

#### Scenario: AC-12 Корректная остановка
- **GIVEN** фоновый процесс работает
- **WHEN** поступает SIGINT или SIGTERM
- **THEN** новые операции прекращаются, браузеры и хранилище закрываются
- **AND** возможное внешнее создание остаётся отмеченным для сверки после следующего запуска

### Requirement: Границы интеграций MVP

Сервис MUST работать для одного пользователя и одного канала через Playwright без Pinterest API, MAX API, IFTTT и сторонних сервисов автоматизации.

#### Scenario: AC-13 Допустимый путь получения материала
- **GIVEN** пользователь сохранил изображение на заданную доску
- **WHEN** сервис импортирует его и планирует публикацию
- **THEN** обнаружение и действия выполняются через браузер, а файл скачивается автоматически по адресу, полученному из представления пина
- **AND** пользователю не предлагается вручную скачивать изображения или подключать стороннюю автоматизацию
