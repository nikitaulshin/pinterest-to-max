# Импорт доски Pinterest

## Purpose

Превращать вручную выбранные пользователем пины одной доски в локально подготовленные изображения с управляемым импортом истории.

## ADDED Requirements

### Requirement: Обнаружение новых пинов заданной доски

Сервис SHALL автоматически находить новые пины доски `https://ru.pinterest.com/mixi56453/max7`, сохранять их Pin ID и адреса источника и изображения и передавать успешно скачанные изображения в очередь.

#### Scenario: PI-01 Новый пин добавляется в очередь
- **GIVEN** история доски инициализирована и пользователь сохранил новый пин с изображением
- **WHEN** выполняется успешная синхронизация
- **THEN** сервис сохраняет Pin ID, URL пина и изображения, скачивает изображение и создаёт одно готовое задание
- **AND** после сохранения пина ручное скачивание или подтверждение импорта не требуется

#### Scenario: PI-13 Рекомендации вне доски
- **GIVEN** рядом с пинами выбранной доски интерфейс показывает рекомендации, рекламу или элементы другой доски
- **WHEN** сервис обходит источник
- **THEN** в импорт включаются только подтверждённые пины заданной доски
- **AND** неподтверждённые элементы не добавляются в очередь

### Requirement: Полный обход динамической доски

Сервис SHALL поддерживать первоначальную и повторную полную синхронизацию с динамической загрузкой пинов и явно отличать завершённый обход от прерванного.

#### Scenario: PI-02 Пины за первой страницей
- **GIVEN** часть пинов появляется только после прокрутки и загрузки следующих элементов
- **WHEN** пользователь запускает полную синхронизацию
- **THEN** сервис обходит доступные элементы до подтверждённого конца доски, включая пины вне первого экрана
- **AND** известный пин в начале доски не прекращает полный обход

#### Scenario: PI-03 Прерванный полный обход
- **GIVEN** загрузка остановилась до подтверждённого конца доски
- **WHEN** истекает ограниченное время ожидания или обнаруживается ошибка интерфейса
- **THEN** синхронизация получает незавершённый результат с диагностикой
- **AND** уже сохранённые пины не теряются, а полная инициализация истории не подтверждается

### Requirement: Максимальное доступное изображение

Сервис SHALL скачивать максимальное доступное разрешение изображения, подтверждённое браузерным представлением пина, и проверять пригодность файла до готовности задания.

#### Scenario: PI-04 Выбор полного изображения
- **GIVEN** пин предоставляет миниатюру и варианты изображения большего разрешения
- **WHEN** сервис готовит изображение
- **THEN** выбирается вариант максимального доступного разрешения, а не миниатюра карточки
- **AND** в источнике сохраняется фактически использованный URL

#### Scenario: PI-05 Ошибка скачивания или неподходящий материал
- **GIVEN** файл скачивается не полностью, ответ не является изображением либо пин содержит только видео
- **WHEN** выполняется импорт
- **THEN** материал не становится готовым заданием на публикацию
- **AND** источник и причина ошибки или неподдерживаемого формата доступны для диагностики
- **AND** остальные подходящие пины продолжают обрабатываться

### Requirement: Повторяемость синхронизации

Сервис MUST сохранять результат повторной синхронизации без повторного задания для известного Pin ID или побайтово одинакового уже обработанного изображения.

#### Scenario: PI-06 Повторная синхронизация
- **GIVEN** пин уже импортирован
- **WHEN** обычная или полная синхронизация снова обнаруживает его
- **THEN** новое задание для этого Pin ID не создаётся
- **AND** его состояние и исходное место в очереди не сбрасываются

#### Scenario: PI-07 Один файл в разных пинах
- **GIVEN** два разных Pin ID дают одинаковые байты изображения
- **WHEN** оба изображения успешно получены
- **THEN** сохраняются сведения об обоих источниках, но существует не более одного задания для этого изображения

### Requirement: Bootstrap без исторических публикаций

Сервис SHALL предоставлять bootstrap, регистрирующий существующие пины без добавления в очередь; обычная синхронизация не должна публиковать историю до явного выбора первоначального режима.

#### Scenario: PI-08 Bootstrap доски
- **GIVEN** доска содержит исторические пины, а пользователь выбрал bootstrap
- **WHEN** полный обход успешно завершён
- **THEN** обнаруженные Pin ID помечены как известная история без новых заданий
- **AND** только впервые обнаруженные после этого пины входят в обычный импорт

#### Scenario: PI-09 Повторный bootstrap и существующая очередь
- **GIVEN** часть заданий уже находится в очереди либо обработана
- **WHEN** пользователь повторяет bootstrap
- **THEN** новые обнаруженные исторические пины регистрируются без очереди
- **AND** существующие задания, дедупликация и результаты планирования сохраняются

#### Scenario: PI-10 Неинициализированная доска
- **GIVEN** для доски ещё не завершён bootstrap или первоначальный backfill
- **WHEN** пользователь запускает обычную синхронизацию либо фоновый процесс
- **THEN** сервис требует явного выбора bootstrap или backfill
- **AND** вся история не добавляется в очередь по умолчанию

### Requirement: Ограниченный backfill

Сервис SHALL импортировать запрошенное положительное целое количество ещё не поставленных в очередь уникальных исторических изображений в порядке обхода доски, начиная с её начала.

#### Scenario: PI-11 Backfill выбранного количества
- **GIVEN** имеется не менее N подходящих уникальных исторических изображений, включая зарегистрированные bootstrap
- **WHEN** пользователь запускает backfill на N изображений
- **THEN** добавляется ровно N заданий с сохранением порядка отбора
- **AND** дубликаты и неподходящие материалы не расходуют N
- **AND** при первоначальном backfill оставшаяся успешно обойдённая история регистрируется без очереди

#### Scenario: PI-12 Недостаток истории и возобновление backfill
- **GIVEN** запрошено N изображений, но подходящих меньше либо обход прерван
- **WHEN** backfill завершается или возобновляется как тот же сохранённый запрос
- **THEN** сервис сообщает фактически добавленное число и причину недобора или незавершённости
- **AND** возобновление не увеличивает исходное N и не создаёт повторных заданий
- **AND** первоначальная инициализация подтверждается только после полного обхода
