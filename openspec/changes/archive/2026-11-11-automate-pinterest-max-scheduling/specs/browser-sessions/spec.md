# Браузерные сессии

## Purpose

Сохранять раздельный ручной доступ к Pinterest и MAX для последующей автоматической работы без передачи паролей сервису.

## ADDED Requirements

### Requirement: Первоначальная ручная авторизация

Сервис SHALL предоставлять ручной вход через браузер отдельно для Pinterest и MAX и сохранять подтверждённую сессию выбранного сервиса.

#### Scenario: BS-01 Первоначальный вход
- **GIVEN** для выбранного сервиса нет действующей сессии и доступно графическое окружение
- **WHEN** пользователь запускает команду авторизации и завершает вход в браузере
- **THEN** сервис проверяет доступ к выбранной доске или каналу и сохраняет сессию
- **AND** пароли и коды входа не запрашиваются CLI и не записываются в логи

#### Scenario: BS-02 Раздельное сохранение сессий
- **GIVEN** пользователь авторизован в Pinterest и MAX
- **WHEN** приложение перезапускается
- **THEN** оно использует отдельную сохранённую сессию каждого сервиса
- **AND** повторный вход в один сервис не заменяет профиль другого

### Requirement: Явная утрата авторизации

Сервис SHALL распознавать отсутствие доступа, прекращать затронутые браузерные операции и требовать повторного ручного входа без потери очереди.

#### Scenario: BS-03 Истечение авторизации
- **GIVEN** сохранённая сессия перестала давать доступ к доске или каналу
- **WHEN** сервис пытается выполнить соответствующую операцию
- **THEN** он сообщает, для какого сервиса требуется ручной вход, и сохраняет задания
- **AND** не повторяет защищённое действие до успешной авторизации
- **AND** если отправка поста уже могла произойти, результат остаётся неопределённым до сверки

#### Scenario: BS-04 Возобновление после входа
- **GIVEN** операции сервиса приостановлены из-за отсутствия доступа
- **WHEN** пользователь завершает повторный ручной вход
- **THEN** последующий цикл возобновляет безопасные операции с сохранёнными заданиями
- **AND** операции с неопределённым результатом сначала проходят сверку

### Requirement: Запрет обхода защиты сайтов

Сервис MUST прекращать автоматические действия при CAPTCHA или антибот-проверке и предлагать ручное восстановление доступа без попыток обхода.

#### Scenario: BS-05 CAPTCHA
- **GIVEN** сайт показывает CAPTCHA или блокировку автоматизированного доступа
- **WHEN** сервис обнаруживает эту проверку
- **THEN** соответствующая интеграция приостанавливается с диагностикой
- **AND** сервис не подключает решатели CAPTCHA, прокси-ротацию или другие средства обхода

### Requirement: Защита профиля от одновременного использования

Сервис MUST исключать одновременную авторизацию и фоновую работу с одним профилем в общем хранилище.

#### Scenario: BS-06 Занятый профиль
- **GIVEN** фоновый процесс уже использует хранилище и профили
- **WHEN** пользователь запускает команду ручного входа с тем же хранилищем
- **THEN** команда отказывает с понятным указанием остановить фоновый процесс
- **AND** работающий профиль не открывается вторым браузером
