# Инструкции для агентов

## Язык документации

Вся документация в репозитории должна быть написана на русском языке.

## Язык ошибок в тестах

Сообщения об ошибках и assertions в тестах должны быть написаны на английском языке.

## Тесты

Добавляйте тест, когда он защищает доменный инвариант, собственное ветвление, безопасность, обработку ошибок, жизненный цикл или найденную регрессию. Поведение библиотек, тривиальные конструкторы, getters и wiring отдельно не тестируются.

## Интеграционные тесты

Приложение не имеет HTTP API. Smoke-тесты проверяют запуск и завершение через публичную команду процесса. Будущие сценарные тесты проверяют наблюдаемое поведение приложения. Отдельные тесты подключений к БД, миграций и wiring не нужны. Один тест проверяет один кейс; каждый отдельный сценарий оформляется отдельным тестом.

## Доменная модель

Сущности и value objects создаются через конструкторы, а наружу экспортируется только предметное поведение и минимальный доступ к состоянию, необходимый соседним слоям.

## Комментарии в коде

Комментарии помогают быстро понять код без чтения тела. Пишите простой фразой, что делает сущность и какое важное поведение не видно из её имени: например, атомарность, ограничение или формат данных. Публичные идентификаторы документируются в формате языка.

## Отступы в коде

Разделяйте пустой строкой смысловые этапы функции: подготовку данных, проверки, внешние вызовы и возврат результата. Связанные строки оставляйте одним блоком.
