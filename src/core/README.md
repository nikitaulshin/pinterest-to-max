# Внутренняя логика

`queue.ts` содержит правила задания и FIFO без Playwright, селекторов, Pinterest
и SQLite. Хранение и атомарные изменения находятся в `../storage.ts`, браузер
и подготовка файлов — в `../integrations/pinterest/`.

`QueueJob` создаётся через конструктор. Пропуск разрешён для ready/failed
без внешнего поста, повтор — только для failed без поста с возвратом в ready.
Preparing/submitting/uncertain/scheduled защищены; uncertain требует сверки MAX.
Эти будущие состояния пока не создаются работающим приложением. Хранилище
записывает прежнее состояние в queue_events, сохраняет ошибку, ID, файл
и исходное место задания, очищая next_attempt_at при ручном переходе.

`nextReadyJob` выбирает ready без max_post_url с наступившим временем повтора,
по added_at, затем ID. Отложенный повтор не блокирует другие готовые задания.
В queue list результат возвращается как nextReadyId из read-only снимка;
это не захват задания. Worker и расчёт дат публикаций ещё не реализованы.

Источник и файл отделены от задания: failed источника при скачивании не создаёт
job и не исправляется через queue retry. Дедупликация Pin ID/SHA-256, история
bootstrap/backfill и единственный владелец DATA_DIR обеспечиваются хранилищем
и точкой запуска. Хеш сравнивает байты, а не визуальное сходство.

Команды и границы — в [корневом README](../../README.md), термины —
в [доменном контексте](../../docs/agents/domain.md).
